# modform Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local-only training dashboard on a Raspberry Pi 4 (4 GB) that answers "am I improving?" and "am I overtraining?" from Garmin data, with a twice-daily written review from Claude (API).

**Architecture:** garmin-grafana's sync container (patched) fills InfluxDB 1.11. A new zero-dependency Python app (`modform`) reads InfluxDB over its HTTP API, computes every verdict in pure functions, asks the Claude API to write the review from the findings (template text as fallback), stores reviews in SQLite, and serves one static HTML/JS/CSS page. Everything runs in one Docker Compose file.

**Tech Stack:** Python 3.13 stdlib for the app (`http.server`, `urllib`, `sqlite3`, `zoneinfo`, `statistics`) plus the `anthropic` SDK; pytest for tests (dev only); InfluxDB 1.11; Docker Compose; plain HTML/JS/CSS with inline SVG.

**Spec:** `docs/superpowers/specs/2026-11-04-training-dashboard-design.md`

## Global Constraints

- Hardware: Raspberry Pi 4 Model B, 4 GB RAM, SSD. No model runs on the Pi.
- Python everywhere. App runtime dependencies: stdlib + **`anthropic`** (pinned exact 1.x version) only.
- `python-garminconnect` **≥ 0.3.20** inside the sync container.
- No published ports except the dashboard on **8080** (Pi-hole owns 80). InfluxDB: internal network only.
- Every image pinned to an exact version or commit; never `:latest`.
- Garmin token folder owned by uid 1000, mode `700`. No Garmin password stored (not even base64). Secrets in `.env`, mode `600`.
- Claude never decides a verdict or gauge state; it writes the review from findings + period summary computed in code. Every number in its text must appear in its input, else template text.
- Only recorded activities count. Nothing about future/planned sessions.
- Never flag the owner's usual pattern as a problem by itself.
- The Claude's take panel is never empty: template text whenever the API can't be used (no key, error, timeout, refusal, failed number check).
- Model `claude-sonnet-5-5`, `output_config={"effort": "low"}`, server-side fallback `fallbacks="default"` (beta `server-side-fallback-2026-07-01`). Only findings + the Report summary are sent; never credentials or per-second data.
- Panel label: **"Claude's take"**. Verdicts: **Yes / No / Mixed** (+ "Building your baseline"). Gauge: **fresh / normal / strained**.
- Palette `#2347A8 #151515 #F2A922 #F3A6B5 #E8502F #F4EEE1 #FBF8F2`; Anton + Work Sans, self-hosted; WCAG AA contrast; works at phone width.
- "Month" = rolling 28 days. Weeks are Mon–Sun in the owner's local timezone (`TZ`, default `Europe/Lisbon`).

## Review Focus

1. **UTC vs local time.** Garmin stores UTC; a Sunday 23:30 local run must land in that week, and "nights" must be local dates. → `test_week_uses_local_timezone` in Task 6.
2. **garmin-grafana writes two `ActivitySummary` points per activity** (start + an `activityName == "END"` marker). Each activity must count once. → `test_end_markers_ignored` in Task 2.
3. **Missing data** (watch not worn, no HR, no training load, manual entries): nothing crashes, gauge uses what exists, effort falls back. → `test_effort_fallbacks`, `test_gauge_missing_nights` in Tasks 3 and 5.
4. **API hangs / no internet / Pi reboots mid-review:** job must finish with template text, not stay "writing" forever. → `test_timeout_falls_back` in Task 8, `test_stale_job_recovered` in Task 9.
5. **Review pressed twice / during a scheduled run:** one review at a time; second request gets "busy", not a second paid call. → `test_single_job_at_a_time` in Task 9.

### Task 3: Running analysis

**Files:** Create `app/modform/analysis/__init__.py`, `app/modform/analysis/running.py`, `app/tests/test_running.py`

**Interfaces:**
- Consumes: `Activity`, `Sample`.
- Produces:
  - `effort(a: Activity) -> Literal["easy","moderate","hard"]` — by `training_load`: `< EFFORT_LOAD_MODERATE (50)` easy, `< EFFORT_LOAD_HARD (120)` moderate, else hard. If load is `None`: by `aerobic_te` (`<2.5` easy, `<3.5` moderate, else hard). If both `None`: `"easy"`.
  - `is_strength(a: Activity) -> bool` — `"strength" in sport or "hiit" in sport`.
  - `is_run(a: Activity) -> bool` — `"running" in sport`.
  - `after_strength(run: Activity, others: list[Activity], window_h: float = 2) -> bool` — true if some strength activity ended ≤ `window_h` hours before `run.start` (and not after it).
  - `pace_at_hr(samples: list[Sample], lo: int = 135, hi: int = 145, min_s: int = 300) -> float | None` — seconds per km over samples with `lo ≤ hr ≤ hi` and `speed > 0.5`; `None` if fewer than `min_s` seconds qualify.
  - `RunningTrend(current: float | None, change: float | None, points: list[tuple[date, float]], direction: Literal["up","down","flat"] | None)` — `change` in s/km, negative = faster; `direction` "up" = improving.
  - `running_trend(acts: list[Activity], samples_for: Callable[[str], list[Sample]], end: date, weeks: int = 6) -> RunningTrend`

`running_trend` algorithm (not determined by the signature): qualifying runs = `is_run`, not `after_strength`, start within `weeks` before `end`. Per run: `pace_at_hr(samples)`; if no samples, use `1000/avg_speed` only when `lo ≤ avg_hr ≤ hi`. `current` = mean of the last 3 points; `change` = mean(last 3) − mean(first 3), needs ≥ 4 points else `None`. `direction`: `change ≤ -3` → "up", `≥ +3` → "down", else "flat"; `None` when `change` is `None`.

### Task 5: Recovery, usual pattern and gauge

**Files:** Create `app/modform/analysis/recovery.py`, `app/tests/test_recovery.py`

**Interfaces:**
- Consumes: `Night`, `Activity`, `effort()`.
- Produces:
  - `Baseline(hrv: tuple[float,float] | None, rhr: tuple[float,float] | None, sleep: tuple[float,float] | None)` — each `(mean, sd)`; `None` if fewer than `BASELINE_MIN_NIGHTS` (14) values.
  - `baseline(nights: list[Night], end: date, days: int = 42) -> Baseline` — uses nights in `(end-3-days, end-3]` (excludes the 3 judged nights).
  - `signals_off(n: Night, b: Baseline) -> int` — HRV `< mean − sd`, RHR `> mean + sd`, sleep `< mean − sd`; missing value or missing baseline → not off.
  - `week_load(acts: list[Activity], end: date, days: int = 7) -> float` — sum of `training_load` (None → 0).
  - `usual_week_load(acts, end: date, weeks: int = 8) -> float | None` — median of 8 full Mon–Sun weeks before `end`'s week; `None` if fewer than 4 weeks have any activity.
  - `usual_hard_pairs(acts, end: date, weeks: int = 8) -> set[tuple[int,int]]` — weekday pairs `(d, d+1)` (0=Mon) where both days had a "hard" activity in ≥ half of those weeks.
  - `Gauge = Literal["fresh","normal","strained","building_baseline"]`
  - `gauge(nights: list[Night], acts: list[Activity], end: date) -> Gauge`

Gauge rule (spec, verbatim intent): judged nights = last 3 nights ending `end`. `building_baseline` if all three baselines are `None`. **strained** if ≥ 2 of the 3 nights have `signals_off ≥ 2`, **or** (`week_load > LOAD_HIGH_FACTOR (1.25) × usual` **and** any judged night has `signals_off ≥ 1`). **fresh** if no judged night has any signal off **and** (`usual is None` or `week_load ≤ usual`). Else **normal**. Load alone never gives strained.

### Task 8: Writer (Claude with fallback)

**Files:** Create `app/modform/writer.py`, `app/tests/test_writer.py`

**Interfaces:**
- Consumes: `findings` list, `Report` (Task 6), `config.GOAL`, `config.ANTHROPIC_API_KEY`, `config.CLAUDE_MODEL`.
- Produces:
  - `numbers_ok(text: str, source: str) -> bool` — every number token in `text` (regex `\d+(?:[.:,]\d+)*`) appears in `source`.
  - `write_review(fs: list[str], report: Report, client=None) -> tuple[str, Literal["claude","template"]]` — `client` injectable for tests; default `anthropic.Anthropic(timeout=60.0, max_retries=2)`.

API call (SDK, non-streaming — output is short):
```python
client.beta.messages.create(
    model=config.CLAUDE_MODEL, max_tokens=2000,
    output_config={"effort": "low"},
    betas=["server-side-fallback-2026-07-01"], fallbacks="default",
    system=SYSTEM,  # fixed string, see below
    messages=[{"role": "user", "content": payload}],
)
```
`payload` = `"Goal: " + GOAL` + findings as bullets + `json.dumps(dataclasses.asdict(report), default=str)`. `SYSTEM`: "You write a short weekly training review for one person from their Garmin data. Write one friendly paragraph of at most 150 words. The verdicts in the findings are final; don't contradict them. You may point out patterns visible in the summary. Use only numbers that appear in the input. No medical advice, no plans or future workouts." Use text from `text` blocks only. Template fallback `(template_text(fs), "template")` when: key empty (no call made), any `anthropic.APIError`/`APIConnectionError`/`APITimeoutError`, `stop_reason in ("refusal", "max_tokens")`, empty text, or `not numbers_ok(text, payload)`. Log the reason (no payload in logs).
